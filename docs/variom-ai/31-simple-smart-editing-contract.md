# VARIOM — Simple Smart Editing Contract

**Version:** 1.0 | **Status:** NORMATIVE DRAFT | **Authority:** Documents 00, 19–29; owner-approved scope and recovered source catalogue.

## 1. Purpose and product boundary
Smart Editing is a simple task-based workflow for improving an existing video. It is not a professional timeline editor, arbitrary effects platform or new-scene generation tool. The original input MUST remain unchanged; each editing result is a separate output asset.

## 2. Approved task catalogue
The six task entries are:
1. **Auto Captions** — create and place captions from detected speech where supported.
2. **Audio Enhancement** — improve intelligibility/quality of source audio where supported; no unsupported advanced audio controls.
3. **Silence Removal** — detect and remove or shorten silence according to the supported operation; preserve intelligible speech and continuity.
4. **Music & Rhythm** — add or align licensed/authorized music to the edit where capability and rights are verified.
5. **Motion Graphics** — add selected graphics from the six categories below.
6. **Additional Instructions** — clarify selected supported tasks; cannot create a new capability or override policy.

## 3. Motion Graphics categories
- Kinetic Typography
- Highlights & Callouts
- Icons & Infographics
- Product Features
- Shapes & Effects
- Titles & Lower Thirds

Multiple selections may be allowed only where the verified processing path supports them. A category name alone does not establish executable capability.

## 4. Inputs and outputs
Inputs:
- one authorized source video asset;
- selected approved task(s);
- selected Motion Graphics category/categories where applicable;
- concise additional instructions;
- language/context and Brand DNA only where relevant and authorized.

Output:
- a separate edited video asset;
- operation/task provenance;
- supported output metadata;
- completion/failure status and Content Library entry when successful.

The source asset is immutable. No product catalog, timeline, tracks, frame-by-frame controls, arbitrary effect graph or new-scene generation is introduced.

## 5. Validation and capability gates
- Confirm source ownership, media validity and supported input characteristics.
- Each selected task must map to a verified capability and compatible input.
- Reject unsupported combinations before quote/confirmation.
- Music use requires rights/licensing evidence; no arbitrary copyrighted track is assumed available.
- Additional Instructions are bounded by selected supported operations.
- Do not expose controls for a task whose processing path is not verified.
- Provider-specific codecs, durations, file sizes and output limits remain in the evidence register.

## 6. Cost and execution
- Present a server-derived quote for the selected operation set before explicit authorization.
- Reserve credits only after confirmation.
- Execute only after reservation.
- Preserve per-operation outcome and verified actual usage.
- Reconcile partial failures and release unused reservation; unknown provider outcome blocks blind retry.
- No illustrative or guessed cost is presented as live.

## 7. Failure and recovery
- Invalid/unsupported input: no reservation.
- Unsupported task combination: identify incompatible selection and preserve other valid choices.
- Provider failure: reconcile usage; keep source unchanged.
- Partial completion: report successful and failed operations; do not claim full success.
- Persistence failure: retain recoverable job state; no success until output and library entry are durable.

## 8. Acceptance criteria
- Exactly six approved task entries and six motion categories are represented.
- Only verified capabilities are executable.
- Source is preserved and output is separate.
- No professional editor or excluded feature appears.
- Rights for music/assets are checked.
- Cost/credit lifecycle follows Document 26.
- Successful output is automatically saved to Content Library.
