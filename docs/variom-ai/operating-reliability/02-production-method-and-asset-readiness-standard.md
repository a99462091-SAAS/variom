# VARIOM — Production Route & Asset Readiness Control

**Document ID:** V-OR-02  
**Version:** 0.2-draft  
**Status:** DRAFT — OWNER REVIEW REQUIRED  
**Authority:** Master Strategy V1.2 and applicable approved knowledge documents.

## 1. Purpose

Operationalize route selection and asset readiness for a task that passed R1. Use the least complex suitable method that satisfies the approved brief, quality needs, rights, and fidelity requirements. This is not an independent production workflow and does not authorize spending.

## 2. Classify only material inputs

Record material assets and information using these practical classes:

- **PROTECTED SOURCE:** must remain authentic where exact fidelity is required (e.g., official logo, actual package/product image, labels, model identifiers, certification marks, customer footage).
- **GENERATABLE:** non-factual, non-identity-bearing elements allowed to be created (e.g., background, atmosphere, abstract decoration).
- **EDITABLE:** source element with explicitly permitted operations (crop, resize, masking, retouching, etc.).
- **VERIFIED INFORMATION:** text or factual information that must be transferred accurately from an identified source.

This classification is task-dependent. It does not impose an authentic-product-image requirement on tasks where such an asset is irrelevant.

## 3. Asset and route checks

For each essential asset, record its source, availability, required fidelity, allowed/prohibited transformations, and relevant rights/usage limits if known. Do not infer usage rights from possession.

Choose a route proportionate to the task: direct layout/compositing, generation of permitted elements, editing, enhancement, montage, or a combined workflow. Prefer compositing authentic protected sources over model recreation when fidelity matters. Use placeholders only in clearly labeled drafts, or redesign to avoid a false representation.

A model's reference feature or provider claim is **DECLARED** until tested. Record observed capability narrowly: provider/model/version, task type, reference input, conditions, artifact inspected, and result. A successful test does not establish universal capability or guarantee fidelity in other routes.

## 4. R2 outcome

- **ROUTE_READY:** route and essential assets are suitable for the next authorized step.
- **READY_WITH_LIMITATIONS:** limitations are documented and do not violate mandatory requirements.
- **BLOCKED:** essential asset, rights, capability, or feasibility issue cannot be safely resolved.
- **OWNER_DECISION_REQUIRED:** material exception or unresolved risk requires owner authority.

R2 route readiness is not financial authorization, execution permission, or quality acceptance.

## 5. Protected-asset rules

Where exact fidelity is required: do not regenerate protected assets; use source placement/compositing where feasible; preserve protected content through edits; compare transformed source to the original; never present generated substitutes as official; do not infer facts from visual resemblance; and do not pass final if fidelity cannot be verified.

## 6. Negative cases

Validate existing R2-N01–N10 cases, covering protected asset regeneration, missing sources, misleading substitutions, unsupported capability claims, unverified reference adherence, route mismatch, rights uncertainty, fidelity failure, prohibited transformation, and route readiness incorrectly treated as execution authorization.

## 7. Record and governance

Capture route, concise rationale, essential assets and handling, capability evidence state, restrictions, limitations, and outcome in the **Unified Task Execution Record**. Do not create a separate asset report unless a task-specific artifact is genuinely needed.

Draft only; owner acceptance is required before adoption or implementation.

**Operating rule:** Select a feasible route based on evidence and task needs; never treat a provider promise as proof or route readiness as permission to spend.
