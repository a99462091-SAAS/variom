# VARIOM — Operating Reliability Standards

**Status:** Draft operational companion set — owner review required  
**Parent authority:** [Intelligent Advertising Strategy & Operating Framework V1.2](../intelligent-advertising-strategy/00-master-strategy.md)

These standards translate the approved strategy's existing operating, provider-selection, quality, approval, and simulation requirements into checkable procedures. They do not replace or outrank the master strategy or the six approved knowledge documents.

## Standards

| Sequence | Document | Purpose |
|---|---|---|
| R1 | [Decision & Creative Brief Readiness](01-decision-and-brief-readiness-standard.md) | Validate approved direction, applicable knowledge, claims, assets, and brief readiness |
| R2 | [Production Method & Asset Readiness](02-production-method-and-asset-readiness-standard.md) | Classify assets, protect authentic sources, assess routes and provider evidence |
| R3 | [Output Quality, Repair & Acceptance](03-output-quality-repair-and-acceptance-standard.md) | Inspect actual outputs, classify defects, control repairs, and determine acceptance |
| R4 | [Simulation & Validation](04-simulation-and-validation-standard.md) | Test success and failure behavior, record evidence, and manage regression and owner review |

## Test evidence

- [perFIX POST 01 reliability replay — 2026-11-24](test-results/perfix-readiness-replay-2026-11-24.md): partial manual simulation of R1–R3 decision logic and document consistency. It is not a provider test, actual artifact inspection, or platform test.

## Mandatory boundaries

- R1 readiness is not permission to execute.
- R2 route suitability is not financial authorization.
- Successful generation is not quality acceptance.
- Quality PASS is not customer final-content acceptance.
- Final-content acceptance is not publication authorization.
- Simulation evidence is not proof of commercial performance or platform implementation.
- Draft standards are not approved shared knowledge or deployed platform controls.

## Adoption sequence

1. Review R1–R4 for consistency with the approved source documents.
2. Obtain explicit owner acceptance of the operational standards.
3. Execute the required simulation and negative tests with evidence.
4. Resolve critical failures and rerun affected regression cases.
5. Obtain separate authorization before implementing these controls in the platform.

Do not represent these documents as implemented controls until the corresponding software behavior exists and has been tested.
